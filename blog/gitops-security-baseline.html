A practical security baseline for GitOps delivery

GitOps · DevSecOps · Supply Chain

A credible GitOps demo should show more than deployment automation. It should demonstrate that artifacts are validated before they reach the cluster and that the runtime still enforces policy.

1. Validate source and manifests

Run fast checks first: unit tests, linting, Helm rendering and Kubernetes schema validation. Fail early before building or publishing artifacts.

helm lint ./charts/my-app
helm template my-app ./charts/my-app > rendered.yaml

2. Scan the image

Use Trivy or another scanner after the image is built and before promotion.

trivy image --severity HIGH,CRITICAL my-registry/my-app:1.4.0

The useful part is not merely running a scanner. Define what severity or policy actually blocks promotion.

3. Produce provenance and sign artifacts

Signing makes the deployment chain stronger because the cluster or admission policy can verify that the artifact came from an approved workflow.

cosign sign my-registry/my-app@sha256:...

Prefer immutable digests for promotion instead of relying only on mutable tags such as latest.

4. Keep deployment changes in Git

Update the desired image digest or chart version in the GitOps repository and let Argo CD reconcile it. Avoid giving the CI pipeline broad direct cluster credentials when GitOps can be the deployment boundary.

5. Enforce runtime policy

Use admission controls such as OPA Gatekeeper or a platform-native policy engine for requirements like approved registries, resource limits, non-root execution and required labels.

Defense in depth: CI checks improve feedback. Admission policy protects the cluster even when a pipeline is bypassed or misconfigured.

6. Make the flow observable

Keep evidence: scan output, artifact digest, signature verification, Git commit and Argo CD sync state. During an incident, these links make it much easier to answer what changed and how it reached production.

A compact pipeline

commit
  ↓
lint + test
  ↓
build image
  ↓
Trivy scan
  ↓
SBOM + Cosign signing
  ↓
publish immutable digest
  ↓
update GitOps repo
  ↓
Argo CD sync
  ↓
admission policy
  ↓
runtime observability

This is enough to demonstrate real DevSecOps thinking without turning a portfolio project into an enterprise security product.
